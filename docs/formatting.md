# 排版规则：公众号正文 → X 推文串

X 普通推文**不吃 Markdown**，公众号那种排版直接搬过去又乱又难读。所以正文要重排成推文串。规则如下（参考实现见 `scripts/wx2x.js` 的 `buildThread()`）。

## 走哪条路

| 条件 | 通道 |
|---|---|
| 正文能被推文串装下（≤12 条，每条约 240 字） | **推文串**（thread） |
| 装不下（会被截断） | **X Articles 长文**（见 [x-articles.md](x-articles.md)） |

## 推文串规则

| 规则 | 做法 |
|---|---|
| 拆串 | 正文按 **240 字/条**攒段，最多 **12 条**（含首条）；超出时末条注明「……（正文较长，余下看原文）」 |
| 首条 | `emoji + 标题`，挂文中前 4 张图（X 每条上限 4 图） |
| 短段落＋空行 | 正文每行视作一段、段间留空行；过长段落先按 `。！？；` 切 |
| 小标题 | `一、` `二、` `1️⃣` `写在最后` 这类行**另起一条**，且不会被孤立在上一条末尾；**公众号的加粗小标题（行内 `font-weight:700`）也算小标题**（抓取时收集 bold 行） |
| 编号 | 行首 `1.` / `（2）` / `3、` 统一成 `1️⃣ 2️⃣ 3️⃣`（用正则避开 `1.5 倍` 这类小数） |
| emoji | 按关键词给首条加一个主题 emoji（🤖 机器人 / ⚡ 算力芯片 / 🧠 模型 Agent / 💻 代码开源 / 📈 商业增长 / 📋 政策组织 / 📊 数据 / 🔬 评测论文）；都不匹配就不加 |
| 去噪 | 删掉「点击上方蓝字关注」「点赞在看」「扫码」「商务合作」「往期推荐」等公众号话术、正文里的裸链接、Markdown 残留 |
| 图片 | 从 mmbiz CDN 重新下载再上传（<15KB 的装饰图跳过）。**推文串**：`fileInput` 全编辑器共用、不随条数增加，图片只能挂首条；**X Articles**：走 `Insert → Media` 把图插进正文（见 [x-articles.md](x-articles.md) 坑 1） |

## 整串零外链（为什么 + 怎么做）

X 对带外链的帖子降权，数据很硬：Buffer 分析 1880 万条帖子，**免费号**的链接帖 2025-03 起中位互动几乎归零，Premium 号仍有触达但明显低于纯文本/图片；X 开源排序代码里 19 个预测目标**独独没有"外链点击"**。属于没有明文规定但系统性吃亏。

所以：

- 推文串**一条都不带链接**（首条尤其不能带——它才是进推荐流的那条）；
- 原文链接由**发送成功后的自回复**承载（`replyToPost()`）：先在同一条会话里定位**串尾**——详情页里连续属于我们自己的那一段，遇到别人的帖子就停。**不能取"ID 最大的自己的帖"**：回复别人的对话帖也会出现在同页且 ID 更大；
- 自回复失败**不影响已发的串**：只记 `link_reply` 日志；
- 手动补发：`node scripts/wx2x.js reply <推文URL> --text "原文：<链接>" --tail`（加 `--dry` 只打字不发送）。

## 预览再发

改版式前先预览（不发帖、不上图）：

```powershell
node scripts/wx2x.js preview "<标题片段或文章URL>"          # 推文串排版 + 会走哪条路
node scripts/wx2x.js preview "<标题片段>" --dry-article    # Articles 演练（不发布、自动删草稿）
```

预览结果写入 `reports/wx2x_preview.md`（每条字数、图片数、完整排版文本）。

## 无正文的帖子

音频/视频/图片帖正文不足 80 字（去空白后）→ 记 `skipped_no_text` 跳过，不硬搬。
